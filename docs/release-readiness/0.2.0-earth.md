# Orbital Vision 0.2.0 — Earth implementation and release gates

Date: 2026-09-04. **Local implementation candidate; NOT approved for publication.**

No push, tag, public release, website change, credential change, or user-cache deletion was performed. The source changes that predated this task were preserved. In particular, the now-unused procedural-star source still contains the user's prior edits; it is no longer imported or instantiated by Earth.

## Implemented

- A sun-lit, static NASA GEOS-5 cloud shell, created lazily only for High. Surface normals and Cesium's Sun direction drive day/night illumination. The shell uses back-face culling and depth-tested alpha, stays at the existing **7.5 km visual offset**, and is not described as real-time weather. Other profiles use the existing imagery cloud layer, never both at once. Failed optional shell rendering falls back once; subsequent non-cloud render failure suspends the engine.
- Restrained sunlight/atmosphere tuning, unchanged real terrain heights, night-only city-light imagery, and no extra procedural-star layer or decorative orbiting selection particles. Bloom is **disabled**: visual inspection found exaggerated yellow city-light halos. Re-enabling it requires a separate visual/performance gate.
- A continuously available local NASA base layer underneath online imagery. Individual tile failures get bounded retries instead of disabling the entire online layer. Imagery initialization retries are bounded. Terrain selection has height/latitude hysteresis, and ocean water effects require a provider water mask. Local night lights load independently of the remote imagery request.
- A default-closed, persisted layer drawer, compact Earth/time/catalog header, expandable provenance and diagnostics. Desktop drawer width is 352 px; narrow screens use the existing bottom sheet. All nine categories and independent focus/visibility remain. Selecting an object replaces the drawer; closing restores its previous state. Narrow-screen camera presets scroll rather than collapse into unreadable labels.
- Default Earth composition targets 76% of the measured free rectangle, constrained in both axes. Default-camera metadata is not overwritten by inspector geometry. Drawer changes do not reset a manual camera. X/Escape/hide return requests coalesce into one default flight after layout settles. Focus/follow offsets now use measured overlays instead of hardcoded inspector widths. Reduced-motion transitions and inspector focus restoration are respected.
- One render policy combines workspace, document, minimized-window, updater and motion activity: continuous / on-demand / suspended. Suspension disables Cesium's default loop and pauses propagation. Updater/fatal-render vetoes survive other resume signals. Worker resume messages are coalesced and queued work yields before propagation, avoiding a rapid-navigation backlog. Hidden preview/selection requests do not propagate until resumed.
- Time Lens uses the existing Cesium clock for lighting. Resuming a suspended forecast first resets the clock's wall-time anchor so it does not advance by the hidden duration; real-time return restores the system-clock mode. SGP4 calculations, coordinates, orbital geometry, sample counts and LOD budgets were not changed.
- Actual `postRender` intervals in a bounded ten-second buffer, median/P95/late-frame ratio, separate CPU render-call time, nullable GPU time, effective target and render dimensions. These are **Cesium render-completion intervals**, not independently observed physical display-swap timestamps. JS heap is not labeled GPU/process memory. Idle/hidden gaps do not degrade quality.
- Target-relative adaptive thresholds (3 poor / 20 stable windows, failed-recovery cooldown), including Eco's 45 FPS ceiling and recovery after optional effects recover. High effective density is capped at 1.5 and 8.3 million pixels; MSAA ceilings are 4/2 with FXAA fallback. Existing interaction-resolution reduction remains.
- Preferences v4: default 60, optional up-to-120 FPS, default-closed drawer, High ceiling for new installations with GPU-based startup selection. Existing quality, locale, units, time and other preferences survive migration. Five locale files include the new controls. Version files and optional-update policy agree on 0.2.0; signing key and CSP were not changed.
- Removed retired Earth identity/performance-card CSS selectors without changing shared status components or redesigning other workspaces.

### Performance interpretation

The script includes a short fixed-High, 1440×900 auto-rotation instrument check with adaptation deliberately held off. This is **not a reference benchmark** and not a before/after comparison. The final completed probe on the Intel integrated GPU returned **34.37 FPS**, with a last ten-second median interval of **28.8 ms** and P95 **34.5 ms**. Thus the 58 FPS / 25 ms acceptance must **not** be marked passed. Normal application startup chooses a lower profile on this GPU and remains adaptive; the harness forces High to test the shader and pixel/MSAA paths.

No measured performance improvement, 120 Hz support, 60-minute memory plateau or native warm-return acceptance is claimed. The final JSON keeps raw per-second observations, viewport/render dimensions and renderer identity instead of substituting theoretical GPU performance. There is no same-device, same-state pre-change FPS capture for this task, so the ≤5% regression target remains unverified.

## Reproduce the local checks

Use the existing project scripts for typecheck, lint, tests, release validation, Rust tests/Clippy and production build. For the optional browser harness, run the Vite dev server on a chosen loopback port, provide `ORBITAL_SMOKE_URL` (default `http://127.0.0.1:1426`), and set:

- `ORBITAL_CATALOG_CACHE`: the real `satellite-catalog-v1` cache directory;
- `ORBITAL_PLAYWRIGHT_MODULE`: an installed Playwright module path when it is not locally resolvable;
- `ORBITAL_CHROMIUM`: the Chromium executable when Playwright's default is unavailable.

Then run `node scripts/earth-visual-smoke.mjs`. It only reads the native catalog, uses an isolated browser profile and writes its report/screenshots under `docs/screenshots/earth-0.2.0`. No test fixture/harness is imported into `index.html` or the production bundle.
